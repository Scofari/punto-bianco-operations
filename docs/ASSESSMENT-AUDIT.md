## Problems found and fixed in this audit

1. Lodging search and status tabs only filtered the current 25-record page. Both lodging and case filtering now run in SQL before pagination. Totals remain accurate even on empty pages.
2. Calendar weeks used the viewer's computer timezone. They now use clinic-local calendar dates and timezone-independent day arithmetic.
3. Transfer headings separated the time from the requested label. The heading now matches the direction/time/name format.
4. The admin coordinator selector included non-coordinator roles. It now offers only active eligible staff.
5. A treated companion's renamed visit left an old name on the primary case. The linked visit's current name is now used.
6. Browser workflow tests depended on a separate load-test session cache and assumed new patients appeared on page one. They now sign into each role independently, search globally, and exercise a different viewer timezone.

The earlier negative-number and full-logo corrections are retained and regression-checked.

## Font inspection

The original `Muller.zip` supplies limited commercial demo weights and separate trial files, not a licensed complete production family. The authorized ExtraBold face is embedded only for basic Latin; Romanian extended characters in that demo face show demo markings, so those characters and unavailable weights use system fallbacks. Trial fonts are not deployed.

The newly supplied `muller (1).zip` contains `Mller.ttf`, `COPYRIGHT.txt` and `README.txt`. Font metadata identifies a single non-variable 400-weight “Müller” font, version dated 7 October 2013, with a placeholder company copyright. Its Unicode cmap lacks `ă/Ă`, `ș/Ș` and `ț/Ț`. The archive contains no grant of web-embedding rights. It is not a full Fontfabric Muller family and has not been deployed. Completing this requirement needs an authorized full family with Romanian glyphs and web-embedding permissions.

## Grant reviewer access later

Keep the repository private, as requested. Once the clinic supplies its GitHub usernames, the repository owner opens the repository's **Settings → Collaborators → Add people**, selects the exact accounts and sends invitations. Reviewers must accept before they can read the private repository. Record acceptance before sending the final repository handoff. Do not add guessed accounts. These steps follow [GitHub's collaborator instructions](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository).
